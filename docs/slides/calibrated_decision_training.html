1.11.1 · 문제 정의

“0.8이라고 말한 사건은 실제로 80% 일어나야 한다”

정확도는 argmax가 맞았는지만 본다. Calibration은 확률 값 자체가 반복 관측의 빈도와 맞는지 본다.

손쉬운 예 · 문의 라우팅
모델이 “결제팀으로 보내라”에 0.95를 준 문의가 100건 있다. 실제로 결제팀 건이 70건이면 정확도는 괜찮아도 확률은 과신이다. 자동 처리 임계값(예: 0.9 이상이면 자동 배정)이 이 숫자를 믿는 순간 오류가 샌다.

SFT·RLVR 뒤의 decision token 확률은 과신하기 쉽다는 관찰이 있다(Yaldiz 등, 해당 실험 조건). 그래서 두 프로젝트는 calibration을 세 층으로 나눠 만든다.

  1. 구조 · 확률을 어디서 읽는가
  2. 학습 중 목표 · 어떤 확률을 맞추도록 gradient를 주는가
  3. 학습 후 보정 · 가중치를 고정하고 temperature를 fitting

+ 보정과 별개인 자동 처리 정책(threshold, abstention)

1.11.2 · 학습 중 목표 Laya

확률 분포 자체에 보상을 준다

target t는 gold[question_id].probabilities를 후보 순서대로 모아 정규화한 teacher 분포다. 실제 사건 빈도가 아니다.

R(q,t) = Σ tk log qk
       + 0.75 · Σ tkqk / ‖q‖₂
       − 1Score · RPS(q,t)
RPS = 1/(K−1) · Σk (Σj≤k qj − Σj≤k tj)²
  • Log score · target에 확률이 있는 후보에 0을 주면 크게 손해. 구현은 log를 −9.21에서 clip.
  • Spherical score · target 방향과의 정렬. 함수 기본 가중치 0.5, 공개 fine-tuning 호출은 0.75.
  • RPS · Score(순서형)에서 누적분포 차이를 벌점. 먼 level의 오류를 더 크게 본다.
세 항 모두 q = t에서 최대다. 그래서 “실제 분포를 그대로 말하는 것”이 이득이다. 단, clipping까지 포함한 모든 수치 영역에서 proper 성질을 단정하지는 않는다.

1.11.2 · 업데이트 절차 Laya

noisy logits 4개 → 그룹 정규화 advantage → loss_rl + loss_ce

  1. 한 입력의 logits z에 평균을 뺀 Gaussian noise를 4번 더해 z̃₁…z̃₄를 만든다.
  2. 각 softmax(z̃i)의 reward Ri를 계산한다.
  3. Ai = (Ri − mean R) / std R. GRPO처럼 그룹 안에서 정규화한다.
  4. LRL = −mean[A·log Pθ(z̃)]. 여기서 log P는 noisy logits의 Gaussian density다. 문장 생성이나 환경 rollout은 없다.
  5. L = LRL + LCE(t, softmax z). encoder와 scorer를 함께 업데이트한다.
  6. σ는 epoch에 따라 0.4 → 0.1로 줄인다.
∇z log P(z̃) = (z̃ − z) / σ² ⇒ A > 0인 noise 방향으로 z 이동
CE도 proper log-score loss다. RL 항의 추가 효과는 CE만 vs CE+RL을 같은 데이터·평가로 비교해야 알 수 있다. 오른쪽에서 세 모드를 같은 seed로 돌려 곡선을 겹쳐 보라.
예제 “결제는 됐는데 주문 내역에 안 보여요” → 결제팀 / 배송팀 / 환불팀. teacher t = [0.60, 0.30, 0.10]. 초기 모델은 환불팀을 과하게 믿는다.
step 0
KL(t ‖ q) · 낮을수록 teacher에 가깝다
이번 step의 noisy 표본 4개 (막대 = softmax(z̃), 점선 = teacher)

toy 설정: z를 직접 파라미터로 둠(실제는 encoder 출력), lr 0.25, 60 step = 3 epoch, gradient norm 3에서 clip. 실제 학습 하이퍼파라미터가 아니다.

1.11.3 · 함정 Laya

무엇을 보정했고 무엇을 측정했는지 같은 사건이어야 한다

ECE가 말하는 것

라이브러리 ECE report는 soft target을 argmax(target)으로 hard label화한다. teacher soft target을 넣었다면 이 ECE는 teacher 최상위 선택과의 일치에 대한 수치다. 실제 outcome calibration의 직접 증거가 아니다.

compute_ece=True는 bucket별 20%를 평가용으로 뺀다. fit 표본이 2,000 미만이 되는 bucket은 전부 fit에 쓰고 ECE에서 제외한다.

confidence 필드 3종

필드정의의미
answer_confidencemax(p)선택한 답이 맞을 확률
confidence (Choice·Score)1 − H(p)/log K분포 집중도

Noul에서 P(true)와 max(P(false), P(true))는 다른 사건이다.

보정 도구 ≠ 정책 도구

fit_binning_map은 top-label confidence를 구간별 실제 정답률로 매핑한다. K개 분포 전체를 다시 학습하지 않는다. fit_abstention_thresholds는 허용 오류율에 맞춰 임계값을 고르는 정책이다. 그 자체로 calibration을 보장하지 않는다.

분할 누수

공개 코드는 질문 단위로 펼친 item을 무작위 분할한다. 같은 state의 다른 질문이 train과 calibration에 동시에 들어갈 수 있다. 우리 실습은 원본 case/document/task ID로 먼저 분할한 뒤 질문을 펼친다.

1.11.4 · 학습 중 목표 decider-2B v10

행동 성공과 outcome belief를 따로 학습한다

Laya가 teacher 분포를 맞춘다면, decider v10은 실제 환경에서 행동하고 그 결과로 학습한다. 아래 수치는 저자의 recipe와 보고이며 원래 trainer를 재현한 결과가 아니다.

0.1

Actor · PPO

π에서 행동을 샘플링해 실행. 성공/실패를 reward로 clipped PPO(clip 0.2). 같은 환경 4회 실행의 leave-one-replicate-out baseline.

0.2

Belief · log score

“이 행동이 성공할 확률”을 예측. target은 환경 법칙(미끄러운 grid 전이확률, bag 구성, minesweeper posterior) 또는 브라우저의 실제 click outcome.

1.0

Rendering consistency · KL

state-first/schema-first, 원래/역순 후보 표현의 분포를 KL로 맞춘다. 문자열 배치에 확률이 흔들리지 않게.

0.7

Retention · KL(v8 ‖ student)

replay row에서 기존 능력 유지. 평균 KL > 0.01 nats 또는 한 row KL > 0.05면 actor/belief를 멈추고 retention만 적용.

T = 1.30 고정. RL 동안 served distribution의 temperature를 바꾸지 않았다. 개선은 새 T를 fitting해서 얻은 것이 아니다.
보고된 결과. exact-law 대비 belief log-score gap 0.473 → 0.219 nats. 일반 Bespoke suite의 calibration은 변하지 않았다고 저자가 함께 명시한다. 모든 질문의 ECE 개선으로 확대하지 않는다.

1.11.4 · rendering consistency decider

후보 순서를 뒤집어도 같은 확률이어야 한다

decoder readout은 letter 위치(A/B/C)에 편향이 생기기 쉽다. v10은 같은 state를 여러 방식으로 렌더링해 두 분포의 KL을 줄인다(계수 1.0).

  • state-first ↔ schema-first
  • 원래 후보 순서 ↔ 역순

비교는 내용 기준으로 정렬한 뒤 한다. 역순 렌더링의 A는 원래 렌더링의 C와 같은 후보다.

LLM 학습에 비유하면 data augmentation을 loss로 묶은 것이다. 확률이 문자열 배치에 덜 흔들려야 이후 보정한 T가 의미 있다.

1.11.5 · 학습 후 보정 decider

실제 serving readout을 그대로 fitting한다

Score의 isolated-levels 경로는 level마다 [no, yes] 두 logits를 먼저 보정하고 합친다.

rk(T) = softmax([zk,no, zk,yes]/T)yes
pk(T) = rk(T) / Σj rj(T)

fitter는 이 최종 Score 분포의 gold NLL을 최소화한다. 단순 5-way softmax로 구현하면 같은 T라도 다른 분포가 나온다. 같은 보정이라고 부를 수 없다.

  • 가중치 · readout · 후보 순서 · 정밀도 · schema layout을 고정하고 그 경로에서 logits를 수집한다.
  • temperature_by_type, schema-first용 별도 map, 일부 stock 모델의 T(n) = max(Tmin, a + b·log n)이 runtime에 있다. T(n)은 fit_by_type이 학습하지 않는다.
  • scalar override가 type map을 끄는 경우가 있다. 저장한 config와 실제 적용 값을 같이 확인한다.

같은 logits, 같은 T, 다른 Score 분포

1.11.7 · 우리 실습에 반영할 순서

baseline과 보정부터, RL은 비교 실험으로

  1. 원본 단위로 먼저 분할case/document/task ID로 train · checkpoint validation · calibration · test를 나눈다. 질문과 후보 순서 변형은 같은 split에 둔다.
  2. CE/BCE baseline + 원본 logits 저장hard label · teacher soft label · 환경 true probability를 구분한다.
  3. 모델 고정 → type별 T fit독립 test에서 NLL · Brier · ECE. Noul은 P(true) event calibration, Score는 전체 level 분포와 ordinal 지표도.
  4. Laya식 실험CE만 vs CE + noisy-logit RL을 같은 seed · data budget으로. log-score 효과와 RL update 효과를 분리한다.
  5. decider식 실험확률 법칙이 알려진 작은 stochastic 환경에서 actor/belief를 분리 비교. belief NLL과 행동 성공률을 따로 보고한다.
  6. 정책은 보정과 별도threshold를 고르고 후보 수 · domain · language별 risk/coverage 확인. 모델 · LoRA · 양자화 · readout이 바뀌면 재보정.
